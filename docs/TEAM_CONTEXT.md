## Цель

Кейс ekt.kz: консультант по каталогу, характеристикам, наличию, аналогам и корзине.
Наше отличие: новичок описывает задачу, получает уточнения, объяснение состава,
проверки совместимости и предложение заказа. Не обещаем полный электромонтажный проект.
За 5 часов приоритет — обязательные критерии кейса, воспроизводимая проверка и README.
Презентации не будет. Прогресс каждого участника должен быть виден каждый отчётный час.

## Что уже собрано

- FastAPI обслуживает API и static HTML/CSS/JS. Не React и не отдельный Node backend.
- `app/ai.py`: Responses API, строгий разбор намерений/полей, уточнения, пояснения.
- `app/catalog.py`: demo/live адаптер; `app/kits.py`: ограниченный комплект кухни.
- `app/commerce.py`: предложения и демо-корзина; `app/main.py`: маршруты/сессии/защита.
- `static/guide.js`: меню новичка, лампа, вопросы/проверки комплекта, список покупок.
- API-контракт — `docs/FRONTEND_API.md`. Не вводить новый формат по догадке.
- Локальные cookie-сессии и корзина хранятся в памяти: один процесс, сбрасываются при рестарте.

## Передача между агентами

Одна задача = один владелец = одна ветка = один PR. В PR укажите:

```text
Task: BE-01 / FE-01 / QA-01
Owner/role:
Base SHA:
Branch + commit:
Что изменено / файлы:
API: unchanged / согласованное изменение:
Проверки и результаты:
Что НЕ проверено:
Зависимость / вопрос другому участнику:
Следующий шаг:
```

Интегратор обновляет общий статус после merge. Остальные пишут отчёты в своих PR,
не редактируют одновременно одну таблицу. PR без ссылки, SHA и проверки — не передача.
