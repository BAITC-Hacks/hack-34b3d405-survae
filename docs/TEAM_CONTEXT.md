# Общий контекст SURVAE

Обновлено 23.09.2026. Проверенная программная база: `b2a0fd0`.
Этот документ — снимок фактов, а не автоматический мониторинг: перед работой сверять main/PR.

## Цель

Кейс ekt.kz: консультант по каталогу, характеристикам, наличию, аналогам и корзине.
Наше отличие: новичок описывает задачу, получает уточнения, объяснение состава,
проверки совместимости и предложение заказа. Не обещаем полный электромонтажный проект.
За 5 часов приоритет — обязательные критерии кейса, воспроизводимая проверка и README.
Презентации не будет. Прогресс каждого участника должен быть виден каждый отчётный час.

## Что уже собрано

- FastAPI обслуживает API и static HTML/CSS/JS. Не React и не отдельный Node backend.
- `app/ai.py`: Responses API, строгий разбор намерений/полей, уточнения, пояснения.
- `app/catalog.py`: demo/live адаптер; `app/kits.py`: ограниченный комплект кухни.
- `app/commerce.py`: предложения и демо-корзина; `app/main.py`: маршруты/сессии/защита.
- `static/guide.js`: меню новичка, лампа, вопросы/проверки комплекта, список покупок.
- API-контракт — `docs/FRONTEND_API.md`. Не вводить новый формат по догадке.
- Локальные cookie-сессии и корзина хранятся в памяти: один процесс, сбрасываются при рестарте.

  свободный AI-поиск показал вместе 3000 К и 4000 К. Данные карточек честные, но

- Текущий локальный запуск: 15 синтетических товаров, НЕ рабочий ассортимент ekt.kz.
- Live-адаптер ранее прочитал одну страницу и карточку. Полнота/качество всего каталога не проверены.
- Реальная запись заказа в корзину ekt.kz не подключена; в материалах был read-only API.
- Нет подтверждённого универсального сборщика любого заказа; проверен узкий кухонный сценарий.
- Качество всех диалогов, фото, файлов и отказов реальной модели не оценено большим набором.
- Публичного общего сервера нет. localhost у каждого свой, `.env` тоже свой.
- Ключ этого ноутбука истекает 24.09.2026; файл и ключ не пересылать и не публиковать.
- Финальная сдача на платформе не выполнена. GitHub push не равен «Сдать решение».

## Ближайшие задачи — предложены, ещё не взяты другими участниками

| ID | Владелец | Задача | Критерий готовности |
| --- | --- | --- | --- |
| QA-01 | INTEGRATOR | Сверить каждый обязательный пункт официального кейса с кодом | Матрица требование → проверка → результат → пробел; без выдуманных выполнений |
| BE-01 | BACKEND | Исправить смешение 3000/4000 К в свободном AI-поиске и вопросы новичку | Строгий фильтр явных параметров; при отсутствии совпадения — честный отказ/отдельное согласование альтернативы; 5–10 regression-диалогов |
| FE-01 | FRONTEND | Сделать состояния понятными пользователю | Ясные уточнения/ошибки/fallback, состав+проверки, явное подтверждение, удобство на узком экране |
| QA-02 | INTEGRATOR | Проверка итоговой main с чистого запуска | Команды README выполняются, общий сценарий проходит, ограничения видны |

Перед началом человек сообщает команде ID задачи и ветку. Назначение в этой таблице
не означает, что агент на другом ноутбуке уже получил задачу или работает.
Публичный деплой и реальная корзина требуют выбора хостинга/разрешённой интеграции,
а не имитации готовности. Решение о приоритете — после QA-01.

## Передача между агентами

Одна задача = один владелец = одна ветка = один PR. В PR укажите:

```text
Task: BE-01 / FE-01 / QA-01
Owner/role:
Base SHA:
Branch + commit:
Что изменено / файлы:
API: unchanged / согласованное изменение:
Проверки и результаты:
Что НЕ проверено:
Зависимость / вопрос другому участнику:
Следующий шаг:
```

Интегратор обновляет общий статус после merge. Остальные пишут отчёты в своих PR,
не редактируют одновременно одну таблицу. PR без ссылки, SHA и проверки — не передача.
