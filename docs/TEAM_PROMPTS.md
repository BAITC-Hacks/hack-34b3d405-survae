# Стартовые сообщения для трёх Codex

Сначала откройте локальный клон КОМАНДНОГО репозитория, сохраните свою незакоммиченную
работу и получите свежую main по TEAM_WORKFLOW.md. Не работайте из старого ZIP.
Вставьте соответствующий текст в новый чат в папке репозитория либо явно попросите
текущий чат перечитать файлы. Это общий контекст через Git, а не доступ к чужим чатам.

## Участник 1 — INTEGRATOR / QA

```text
Мы команда SURVAE, репозиторий BAITC-Hacks/hack-34b3d405-survae.
Твоя роль INTEGRATOR/QA. Участник 2 отвечает за backend, участник 3 за frontend.
Прочитай AGENTS.md, docs/TEAM_CONTEXT.md, docs/TEAM_WORKFLOW.md и docs/FRONTEND_API.md.
Проверь status, remote, текущий SHA, свежую main и открытые PR; сохрани чужую работу.
Твоя задача QA-01: сверить официальный кейс с реализованным и составить матрицу
требование → код → проверка → пробел. Если текста кейса нет, запроси его, не придумывай.
Работай в qa/case-review. Можно менять общие документы и tests/test_acceptance_*.py.
Не переписывай app/ и static/. Перед началом покажи план, файлы и критерии готовности.
Веди очередь интеграции; сливай только согласованные PR после тестов и smoke-проверки.
Никаких секретов, force push, настроек GitHub или финальной сдачи без отдельного разрешения.
В конце дай отчёт по шаблону из TEAM_CONTEXT.md и точную ссылку на свою ветку/PR.
```

## Участник 2 — BACKEND

```text
Мы команда SURVAE, репозиторий BAITC-Hacks/hack-34b3d405-survae.
Твоя роль BACKEND. Участник 1 — интегратор/QA, участник 3 — frontend.
Прочитай AGENTS.md, docs/TEAM_CONTEXT.md, docs/FRONTEND_API.md и docs/TEAM_WORKFLOW.md.
Проверь status, remote, SHA и свежую main; не потеряй локальную работу.
Твоя следующая задача BE-01: понятные уточнения новичку и поиск по параметрам.
Работай в backend/novice-dialogue. Сначала покажи 5–10 проверочных сценариев и план.
Твои файлы app/, data/, backend-тесты; static/ не трогай.
Сохрани три API-метода, действующий контракт, сборку кухни, CSRF, изоляцию сессий,
строгое подтверждение корзины и честные demo/live/fallback. Не обещай универсальную комплектность.
Изменение API сначала согласуй с frontend через интегратора. Секреты не выводи.
После реализации прогони тесты, создай отдельный PR, не сливай его самостоятельно.
В конце дай отчёт по шаблону из TEAM_CONTEXT.md.
```

## Участник 3 — FRONTEND

```text
Мы команда SURVAE, репозиторий BAITC-Hacks/hack-34b3d405-survae.
Твоя роль FRONTEND. Участник 1 — интегратор/QA, участник 2 — backend.
Прочитай AGENTS.md, docs/TEAM_CONTEXT.md, docs/FRONTEND_API.md и docs/TEAM_WORKFLOW.md.
Проверь status, remote, SHA и свежую main; свои изменения из старых папок сначала сравни.
Твоя задача FE-01: понятные состояния помощника и удобный путь от задачи до подтверждения.
Работай в frontend/guided-ux. Твои файлы static/ и frontend-тесты, не app/.
Сохрани карточки, options, kit.checks/unresolved, список покупок, подтверждение, номер версии.
Не выдумывай цены, остатки и совместимость. Состояния loading/error/fallback и demo видны.
Не отключай серверные вопросы при включённом AI. API-ключ никогда не находится в JS.
Перед началом покажи план и критерии, после — проверь браузер и узкий экран.
Изменения API согласуй с backend. Передай PR интегратору, самостоятельно main не обновляй.
В конце дай отчёт по шаблону из TEAM_CONTEXT.md.
```

## Правило короткого цикла

Каждые 20–30 минут: законченный небольшой кусок → проверка → commit/push → ссылка интегратору.
Не ждите ровно конца часа для первого push. У каждого участника должен быть свой
реальный подтверждаемый вклад; не создавайте фиктивные коммиты ради отчёта.
Другой Codex читает PR/общие файлы после fetch или через GitHub, не «угадывает», что сделано.
