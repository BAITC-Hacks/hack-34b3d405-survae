## Воспроизведение в отдельной сборке

Не выполнять merge в чужой рабочей папке. В чистом клоне после fetch и проверки
доступности указанных коммитов:

```bash
git worktree add --detach ../survae-qa-current 449628e1f370bc6bc9570ecafeac667c87fc4da3
cd ../survae-qa-current
git merge --no-commit --no-ff bfbf103d607345e757ef2af027d1c7fdb4de53fe 92bc9ec6ecdc5d83df32fea6428c593accb1d2cf
git write-tree
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
node --test tests/frontend_flow.test.cjs tests/frontend_consultation.test.cjs
```

Затем скопировать только `tests/test_acceptance_*.py` из точного проверяемого
коммита QA PR #7. Для воспроизведения известных дефектов:

```bash
python -m pytest tests/test_acceptance_*.py --runxfail -q
```

На macOS shell разворачивает этот glob; в PowerShell перечислить четыре файла
явно. Ожидаемый результат текущей сборки: 4 failed, 2 passed.
Запуск по README выполняется из корня этой сборки. Для одинакового контрольного
режима задавать demo явно, выключать локальную настройку; отдельно включать свой
локальный ключ для live AI. В проверке использован порт 8001 и явная подпись версии
`QA main449628e BEbfbf103 FE92bc9ec`, чтобы не спутать её с чистой main.
