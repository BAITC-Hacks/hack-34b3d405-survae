# Одна общая версия для трёх участников

Общая проверенная версия — ветка `main` командного репозитория.
Она содержит демо-основу, бэкенд комплектования и новый фронтенд.

## Получить общий результат

В терминале внутри своей копии репозитория:

```bash
git status
```

Если есть несохранённые изменения, сначала закоммитьте свои файлы в своей рабочей ветке.
Не используйте reset --hard и не перезаписывайте локальную работу.
Когда рабочая папка чистая:

```bash
git fetch origin
git switch main
git pull --ff-only origin main
git rev-parse --short=7 HEAD
```

Если `--ff-only` сообщает о расхождении, остановитесь и передайте сообщение интегратору.
Не используйте force push. Номер последнего коммита у всех должен совпасть.

## Запуск Windows

Первый запуск (Python 3.11+):

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Если `.env` ещё нет, скопируйте `.env.example` в `.env` и заполните свои настройки.
Не перезаписывайте существующий `.env`, не пересылайте ключи и не коммитьте секреты.
Для одинаковой контрольной проверки используйте `CATALOG_MODE=demo`, без ключа AI.

Остановите ранее запущенный сервер сочетанием Ctrl+C в его терминале. Затем:

```powershell
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://localhost:8000 и обновите страницу с Ctrl+F5.
Внизу боковой панели отображается версия, прочитанная при старте сервера. Она должна
совпасть с `git rev-parse --short=7 HEAD`. Если номер старый — запущен старый процесс
или другая копия репозитория. Каталог/AI могут отличаться при разных локальных `.env`.

`localhost` всегда означает собственный компьютер. Одинаковая ссылка на двух ноутбуках
не означает один сервер. Для общего публичного адреса нужен согласованный хостинг;
GitHub хранит исходники и сам FastAPI не запускает. Этот репозиторий не публикует приложение
автоматически. Демо-корзины у разных браузеров и компьютеров независимы.

## Что проверить вместе

1. «Помогите мне выбрать» → «Собрать подсветку кухни».
2. Ответы: 2 м → есть розетка → сухое место → тёплый свет.
3. Появляются состав, назначение компонентов и проверки комплектности.
4. До подтверждения корзина не меняется; после него — две строки на 10900 ₸ в demo.
5. Новый диалог → подбор лампочки по маркировке; старый сценарий не должен продолжаться.
6. Поиск DEMO-C16-Z → аналог, поиск DEMO-C16-A → характеристики и учебный документ.

## Дальнейшая работа

- Участник 1 — интегратор: проверяет pull request, объединяет и проверяет общий сценарий.
- Участник 2 — бэкенд: API, данные, AI, проверки комплектования и корзина.
- Участник 3 — фронтенд: интерфейс и отображение ответов API.

Перед новой задачей получите свежую `main`, затем создайте отдельную ветку:

```bash
git switch -c backend/next-task
```

Фронтендер использует, например, `frontend/next-task`. Пушьте свои ветки регулярно,
прикладывайте к PR краткое описание и проверку. Перед объединением интегратор получает
обе части и прогоняет `python -m pytest -q`, затем пользовательский путь в браузере.
Для совместной демонстрации запускайте `main`, а не разные рабочие ветки.

В учебном сценарии данные синтетические. Для live-каталога и AI нужны локальные секреты.
Полный комплект из реального ассортимента и запись в корзину ekt.kz требуют отдельной
проверки/интеграции; объединение веток не снимает эти ограничения.
