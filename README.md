# SURVAE · EKT Ассистент

Прототип для HackAlem AI: консультант по электротехническому каталогу, подбор аналогов и корзина с обязательным подтверждением клиента.

Команде: [как получить и запустить одинаковую версию](docs/TEAM_WORKFLOW.md).
Общая версия находится в `main`; состояние приёмки и очередь PR — в
[docs/TEAM_CONTEXT.md](docs/TEAM_CONTEXT.md).
Начните с текстового запроса в чате, например «Хочу подсветку кухни».
Точные проверенные версии и ограничения — в [отчёте общей сборки](docs/CURRENT_INTEGRATION_REVIEW.md).

## Быстрый запуск

Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
test -e .env || cp .env.example .env
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Без ключей работает явно обозначенный учебный каталог и базовый поиск. Для AI заполнить `OPENAI_API_KEY` в `.env`; `OPENAI_MODEL` по умолчанию `gpt-4o-mini`. Секреты не коммитить.

Для реального каталога задать `CATALOG_MODE=live`, `EKT_USERNAME`, `EKT_PASSWORD` из информационного пакета партнёра. `CATALOG_PAGES=20` загружает репрезентативную выборку до 400 позиций. Детали, цены и остатки читаются из API карточки. Проверка остатка перед подтверждением идёт повторно; при ошибке API добавление блокируется.

## Проверка основного сценария

1. В учебном режиме спросить «Есть DEMO-C16-A?» — характеристики, наличие в Астане, учебный документ.
2. Спросить «Подбери аналог DEMO-C16-Z» — исходная позиция отсутствует, альтернативы совпадают по ключевым характеристикам.
3. Спросить об оплате или доставке.
4. На карточке указать 2, нажать «В список +», затем «Проверить набор». Корзина ещё пуста. Нажать «Отмена» — состояние корзины не меняется.
5. Снова нажать «Проверить набор», проверить состав и нажать «Подтвердить и добавить в корзину». Перейти по `/cart`, обновить страницу: состояние корзины сохраняется в этой сессии, пока сервер не перезапущен.
6. Попытаться добавить больше остатка — операция отклоняется.

Учебные товары и документ имеют явные обозначения DEMO/«Учебный». Они не являются реальными товарами или сертификатами. Корзина прототипа отдельная: создание заказа и запись в корзину ekt.kz не реализованы, поскольку партнёр предоставил только API чтения каталога.

## Архитектура

- FastAPI обслуживает статический интерфейс и API сессии.
- `app/catalog.py`: пагинация EKT, получение карточек, поиск, сравнение характеристик, проверка расхождений в данных.
- `app/ai.py`: OpenAI Responses API разбирает намерение и запрос; цены, остатки и изменение корзины не доверяются модели.
- `app/commerce.py`: подготовка предложения → явное подтверждение → свежая проверка цены и остатка → атомарное изменение корзины. Идентификаторы подтверждения привязаны к сессии, действуют 5 минут и не применяются повторно.
- `app/attachments.py`: извлечение текста из PDF, DOCX, XLSX/XLS, TXT/CSV; изображения требуют AI.
- `static/`: адаптивный интерфейс без сборки и внешних frontend-зависимостей.

Сессии и диалоги хранятся в памяти процесса. Перезапуск очищает корзины. Один процесс подходит для прототипа; для production нужны общее хранилище сессий и официальный интерфейс записи корзины EKT.

## Данные и сторонние компоненты

Реальные данные: API партнёра https://ekt.kz/api/products и https://ekt.kz/api/products/detail?id=515291. Условия покупки: https://ekt.kz/checkout-delivery/. Отсутствующие сертификаты не выдумываются. Поле RECOMMEND не считается списком подтверждённых аналогов.

Учебная выборка: `data/demo_catalog.json`, синтетические данные команды. В разработке использован OpenAI Codex. Библиотеки перечислены в `requirements.txt`; они используются в соответствии с собственными лицензиями. Собственные нейросетевые модели не обучались.

Вложения обрабатываются временно, не добавляются в репозиторий. При подключённом AI запрос и содержимое вложения передаются OpenAI API с `store=false`. Платёжные данные не запрашиваются. Перед публичным развёртыванием отключить `ALLOW_LOCAL_SETUP`, использовать HTTPS и секреты окружения.

## Статус

Прототип: каталог, корзина, обработчики запросов и пошаговый подбор учебного комплекта.
Автоматические проверки находятся в `tests/`. Живой API каталога ранее проверен
на одной странице списка и карточке товара. Автотесты используют локальные правила
и подставленные ответы. Результаты отдельных проверок настоящего AI и найденные
дефекты привязаны к SHA в [QA-отчёте](docs/CURRENT_INTEGRATION_REVIEW.md).

## Бэкенд: комплектование и контракт из трёх методов

Для отдельного фронтенда см. [docs/FRONTEND_API.md](docs/FRONTEND_API.md) и готовый
[клиент fetch](docs/frontend-client.js). Достаточно `GET /api/cart`, `POST /api/chat`,
`POST /api/cart/confirm`. Первым запросом GET получите cookie сессии и CSRF-токен.
Поддерживаются CORS для localhost:5173, структурированные ответы `stage/options/kit`,
отмена предложения и новый диалог через `action` в `/api/chat`.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Если `py` отсутствует, используйте установленный `python` версии 3.11+.
Не перезаписывайте уже заполненный `.env`. Активация окружения не требуется.
Пример `.env` содержит только пустые секреты: заполните их самостоятельно.
Документация API — `/docs`. Проверка:

```powershell
.venv\Scripts\python.exe -m pytest -q
```

### Что добавлено

- `app/kits.py`: пошаговое уточнение длины, готовой розетки, сухости места и оттенка света.
- Учебный проверяемый комплект модульной подсветки на 1–4 целых метра. Код проверяет напряжение,
  мощность с запасом 25% (правило этого учебного сценария), совпадение системы/разъёма и состав упаковки.
- Товары из `data/demo_kits.json` синтетические; это не ассортимент и не цены ekt.kz.
- При OPENAI_API_KEY свободные ответы разбираются через Responses API и строгую JSON-схему.
  Без ключа работают локальные правила; при ошибке AI ответ помечается `engine=fallback`.
- В режиме live ищутся реальные кандидаты, но комплект НЕ объявляется полным без обязательных
  полей совместимости. Синтетические позиции никогда не подставляются вместо реальных.
- Текст «да» в чате не меняет корзину. Для подтверждения используется отдельный метод с ID предложения.
- Тесты проверяют сценарий комплекта, CSRF, CORS, изоляцию сессий, повтор подтверждения, изменившуюся
  цену/остаток, атомарность заказа, недостоверные количества, отсутствие данных и ошибки AI.

### Ограничения этой версии

Это один проверяемый сценарий комплектования, а не универсальное проектирование электрики.
Признак `complete` относится к заявленным условиям и данным комплектации выбранной системы.
Широкий подбор реальных комплектов требует маппинга характеристик и подтверждения совместимости партнёром.
Фронтенд в `static/` отображает серверные `options/kit`, причины выбора компонентов и проверки комплекта.
Прототип не резервирует складские остатки и не создаёт заказы на ekt.kz.
Все сессии, предложения и корзины хранятся в памяти одного процесса; не запускайте несколько workers.
Реальные запросы OpenAI требуют личного API-ключа; автоматические тесты не расходуют кредиты.

Документация формата OpenAI: https://developers.openai.com/api/docs/guides/structured-outputs

## Автоматическая проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
node --test tests/*.test.cjs
```

Node.js нужен только для frontend-тестов; для работы сайта сборка JS не требуется.
На Windows можно перечислить существующие `.test.cjs` файлы явно.

Тесты проверяют каталог и сертификаты, аналоги, условия покупки, подтверждение,
повтор, ограничения количества, атомарность, CSRF, изоляцию сессий и извлечение файлов.
Они не расходуют кредиты AI и не подтверждают реальную запись заказа на ekt.kz.
Количество прошедших тестов зависит от точного коммита. **XFAIL и SKIP не являются
прохождением требований**; для воспроизведения известных дефектов:

```bash
python -m pytest tests/test_acceptance_*.py --runxfail -q
```

Acceptance-тесты публикуются в QA PR #7. Для сборки из актуальных PR и повторения
проверок см. [CURRENT_INTEGRATION_REVIEW.md](docs/CURRENT_INTEGRATION_REVIEW.md).
Не заменяйте текущий репозиторий старым ZIP. После каждого обновления main сверяйте
SHA, перезапускайте сервер и повторяйте затронутый сценарий.

## Локальная настройка AI

Задайте `OPENAI_API_KEY` только в локальном `.env` и перезапустите сервер.
Для одинаковой проверки команды используйте `CATALOG_MODE=demo`; отдельно
проверяйте работу без AI и с ключом именно этого ноутбука.
Альтернатива для локальной разработки: `ALLOW_LOCAL_SETUP=1` и страница `/setup`.
Форма проверяет ключ платным запросом и сохраняет его только после успешного ответа.
На публичном сервере форму не включать. Не публикуйте `.env`, ключи или cookie.
